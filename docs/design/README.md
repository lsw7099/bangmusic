## 2. 확정된 전제

- 구매자가 자기 음악 서버에 연결하는 **자가호스팅 제품**. 판매자는 음원을 제공하지 않는다.
- 설계 문서를 먼저 작성하고 그 뒤 구현한다.
- Android 1차에 스트리밍과 오프라인 재생 모두 포함. iOS는 같은 API로 나중에 추가.
- 서버 패키지와 앱은 분리 배포. 앱 구매 권한과 음악 서버 인증은 분리.
- 고객 음악·목록·감상 기록·서버 접속 비밀값을 판매자 측으로 보내지 않는다.

## 3. 이 설계의 주요 결정

| 영역 | 결정 | 근거 위치 |
| --- | --- | --- |
| Proxmox | Linux VM 안에서 Docker Compose(서버 + 프록시 2개 컨테이너) | 01 §2.1~2.3 |
| 백엔드 | TypeScript(Node LTS) + Fastify + SQLite + FFmpeg CLI, 단일 프로세스 | 01 §2.4 |
| 앱 | Flutter. 재생·다운로드·보안 저장소는 인터페이스 뒤에 격리 | 01 §2.5 |
| 곡 ID | 경로와 무관한 영속 ID(ULID) + 원본 파일 매핑 테이블, 내용 해시로 이동 감지 | 01 §4.1~4.3 |
| 미디어 제공 | 불변 "렌디션" 단위. 원본이 바뀌면 410 → 바이트 혼합 불가능 | 03 §4.1 |
| 미디어 인증 | 자원 한정 단기 티켓을 URL에 포함(플레이어·백그라운드 다운로더가 헤더 없이 요청) | 02 §1.4 |
| 변환 | 파일 전체를 변환해 캐시 후 Range 제공. AAC 256/128 두 프로파일 | 03 §4.5~4.6 |
| 오프라인 | 임시 경로에 수신 → 길이·SHA-256 검증 → 원자적 이동 → DB 기록 | 03 §5.5 |
| 만료 정책 | 세션 만료는 다운로드 재생을 막지 않는다. 접근 취소만 잠금. DRM 없음 | 03 §5.8 |
| 외부 가사·번역 | 1차에는 내장하지 않음(서버의 파일과 직접 입력만) | 05 §8.4 |

## 5. 준비서와 다른 점 · 확인하지 못한 점

이전에 전달받은 설계안은 없다. `implementation-brief.md`의 초안과 비교하면 방향(VM, Flutter 후보, 읽기 전용 원본, 영속 ID)은 같고 다음이 다르거나 구체화되었다.

- 준비서는 Android의 Media3 재생·다운로드 문서를 참조한다. 이 설계는 Flutter 패키지(`just_audio`/`audio_service`/`background_downloader`)를 1차 구현으로 제안하며, 그중 `audio_service`는 Media3 세션이 아니라 레거시 미디어 브라우저 서비스 기반이다. 교체 가능하도록 인터페이스로 격리했다(01 §2.5).
- 준비서가 "판매 모델에 따라 결정"으로 남긴 로그아웃·만료 정책을 자가호스팅 전제로 확정했다(03 §5.8).
- 준비서에 없던 항목: 미디어 티켓, 불변 렌디션, Android 17 로컬 네트워크 권한 대응, 서버 주소 재사용 시 토큰 보호, 스토어 심사용 데모 서버.

확인하지 못한 것(문서에 `[확인 필요]`로 표시):

- ~~기존 BangMusic의 소스·테스트를 직접 보지 못했다~~ → **P3에서 확인·이식**(v0.4.6). 셔플/반복·재생 기록·가사 해석을 기존 테스트에 맞췄다(03 §6.3, §6.9, 02 §6). 기존 앱의 발음은 오프라인 형태소 분석기(kuromoji, 사전 포함)로 자동 생성, 가사·번역·표지는 외부 서비스(lrclib, MyMemory 기계번역, iTunes)에서 가져왔다. 새 설계는 05 §8.4에 따라 이 기능을 넣지 않았다 — 오프라인 발음 자동 생성은 **넣기로 결정**(05 §8.4). 외부 서비스는 여전히 넣지 않는다.
- iOS·Android의 형식별 재생 가능 여부, 채택 패키지의 세부 옵션과 종료 후 재생 재개 동작은 실기기 확인 전이다.
- 변환 동시성·캐시 크기·VM 사양의 기본값은 측정 전 가정이다.
- ~~표준 OpenAPI 린터 미실행~~ → P0(2026-10-02)에서 Redocly CLI `recommended` 규칙으로 실행했다. 구조 오류는 없었고, 동작 요약 누락 14건·`GET /server`의 4xx 응답 누락 1건·태그 설명 누락 4건을 고쳤다(`GET /server`에 `429 rate_limited` 추가). 상세는 `../status/P0.md`.
- 스토어 정책·수수료·특허·상표는 판단하지 않았다.
