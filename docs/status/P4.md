형식: 05장 §10.4. 작성 2026-10-03. **P4 수용 기준을 모두 통과했다**(L0 상태 기계, L1 실제 로컬 서버 FN-03·21·22, 실기기 L3 FN-03·15·16·17·21·22). 실기기는 SM-S948N(Android 16/API 36), 서버는 시험 설치(Proxmox LXC 107, HTTP·LAN).

## 구현한 것

- **상태 기계** (`domain/download_state.dart`): 03장 §5.3~5.5·5.7·5.9를 `(행, 사건) → (새 행, 효과)` 순수 함수로. 효과를 저장 전(완료본 이동)·저장 후(파일 삭제)로 나눠 §5.9 쓰기 순서를 지킨다.
- **로컬 DB** (`data/local_db.dart`, drift): 프로필·사용자별 `library.sqlite` — 서버 응답 사본, 다운로드·요청자(곡 하나를 앨범·플레이리스트가 공유), 고정 묶음, 대기 편집, 미전송 재생 기록. 오프라인 검색은 서버와 같은 정규화(`domain/norm.dart` 이식).
- **다운로드 엔진** (`data/download_engine.dart`): 효과 실행, 재시작 대조·고아 정리, 시작 직전 공간·한도 재판단(받는 중인 곡 예약 포함), 세션 만료·잠금, 완료 후 옛 버전 정리·가사·표지(256/1024) 사본.
- **전송**: `platform/transfer_port.dart`(경계, `HttpTransfer` — Range/If-Range, 무응답 시간 초과), `platform/background_transfer.dart`(background_downloader, UIDT·묶음 알림·알림 권한·이어받기).
- **동기화** (`data/offline_sync.dart`): 연결 복귀 시 대기 편집(순서·Idempotency-Key·412 재시도) → 재생 기록(500개씩) → 고정 묶음. 곡이 끝날 때는 재생 기록만.
- **서버 신원 확인** (`core/api_client.dart`): 토큰을 붙이는 첫 요청 전·재연결 후 `GET /server`로 `server_id` 확인, 다르면 토큰·리프레시 미전송(03장 §5.2 [P4 구현]).
- **앱 상태**: 서버 프로필 여러 개·전환·추가, 같은 주소 다른 서버 경고, 로그아웃 시 삭제/보관 선택, 접근 취소 화면 선택지, 세션 만료·서버 변경 시 받은 음악으로 화면.
- **재생**: 받은 파일 우선(재생 시 크기 재확인, 손상 시 스트리밍으로), `source=offline` 기록, 오프라인 복원 시 대기열을 훑지 않음, 저장된 표지·가사.
- **화면**: S9 다운로드 관리(상태 문구 03장 §5.3과 1:1, 저장 공간 막대, 전체 일시중지·재개, 선택 삭제, 크기순/최근순, 큰 글씨 배치), 다운로드 탭 배지, 앨범·플레이리스트 다운로드 버튼, 곡 메뉴, 곡 행 다운로드 표시(스크린리더 문구 포함), 오프라인 홈·라이브러리·검색·앨범·플레이리스트·아티스트, 오프라인 플레이리스트 추가, 설정(S10 일부: 서버, Wi-Fi 전용, 음질, 저장 한도, 로그아웃).
- **Android**: UIDT 권한, 백업·기기 이전에서 `profiles/`와 보안 저장소 제외(03장 §5.7), `MainActivity` StatFs 채널.
- **서버**: 관리 명령 `admin password <사용자이름>`(비밀번호 재설정 — 시험 중 필요해서 추가, 05장 §9.2 방식).

## 발견해 고친 것 (테스트·실기기·자체 검토)

1. 조용히 죽은 연결을 끝없이 기다림 → 무응답 시간 초과 (L1 테스트에서)
2. 실패를 파일 닫기보다 먼저 알려 재시도가 쓰는 중인 `.part`를 자를 수 있음 (L1)
3. 저장소를 닫은 뒤에도 사본 저장이 돎 → dispose가 기다림 (L1)
4. **P3→P4 업데이트 후 두 번째 실행에서 로그인이 풀림** — 옮긴 프로필 목록을 저장하지 않음. 데이터 손실 없음 (실기기)
5. **저장 한도 무시** — 크기를 알기 전에만 판단 (실기기, 처음 시험이 느슨해 놓쳤음 → 시험 강화)
6. 저장 공간 막대가 갱신되지 않음, 최근순이 무작위 ID 순 (실기기)
7. 세션 만료 중 화면이 오류만 보임 → 받은 음악으로 (실기기)
8. 곡마다 전체 동기화, 재시작 후 이어받기가 처음부터 (자체 검토)
9. **로그인 후에는 같은 주소면 `server_id`를 확인하지 않고 토큰을 보냄** (자체 검토, 보안)
10. **서버를 바꿔도 이전 서버의 화면 내용이 남음** (실기기, FN-21)

## 설계에서 정한 세부 (설계 문서에 기록)

- 03장 §5.3: `waiting_login` 상태 추가, 잠금은 행 표시, 재시도 대기는 `queued + not_before`, 완료인데 파일 없으면 사유를 남기고 다시 받기.
- 03장 §5.2: 요청자는 별도 표(`download_requests`), 서버 신원 확인 방식.
- 03장 §5.10: background_downloader 옵션·권한·이어받기 동작 확인.

## 남은 일·알려진 한계

1. **기기 여유 공간 500MB 미만**은 실기기에서 재현하지 않았다(저장 한도로 같은 대기 경로만 확인).
2. "다운로드 자동 업데이트" 설정(03장 §5.4 2단계 자동)은 넣지 않았다 — 지금은 S9에서 "새 버전 받기"를 눌러야 한다. 기본값을 정하지 않은 항목이라 P5 설정(S10)과 함께.
3. 서버에서 영구 삭제된 곡의 "서버에 없음" 표시(03장 §5.4 4단계)는 화면 문구가 없다(다운로드본은 유지된다).
4. 대기열 저장은 아직 SharedPreferences(서버 ID별)이다. 03장 §5.2의 `queue_state` 표로 옮기는 것은 P5 정리 때.
5. 다른 기기·OS 버전(가능하면 API 26~30 기기 1대) 확인은 남음.
6. 시험용 두 번째 서버(LXC 107의 `bangmusic-fn21`, `/var/tmp/bm2`)는 정리했다(2026-10-03). 앱에 남은 그 프로필은 설정에서 로그아웃하면 지워진다.
