## 발견한 문제 · 설계와 다른 점

1. **Dart 생성기의 표지 업로드 결함.** `PUT /playlists/{id}/cover`(본문 `image/*`)에 대해 생성된 `putPlaylistCover`가 이진 본문을 `jsonEncode`한다. 생성기가 `image/jpeg` 본문을 지원하지 않는다는 경고와 일치한다. 이 동작만 앱의 `core/api_client`에서 Dio로 직접 호출해야 한다(모델은 생성물을 그대로 쓰므로 "수작업 모델 금지" 규칙과 충돌하지 않음). P3에서 처리.
2. **생성 패키지의 SDK 하한.** 생성기가 쓰는 `sdk: '>=3.5.0'`은 최신 `json_serializable`이 내는 문법(null-aware elements, Dart 3.8+)보다 낮아 빌드가 실패했다. `gen-dart.mjs`가 생성 후 `^3.8.0`으로 고친다.
3. openapi-generator의 OpenAPI 3.1 지원은 베타다. P3에서 생성 모델의 null 처리·enum의 "모르는 값 무시"(계약 공통 규칙)·`oneOf`(플레이리스트 편집 연산)를 단위 테스트로 확인한다 **[확인 필요]**.
4. `schemas.json`은 OpenAPI 3.1(JSON Schema 2020-12) 스키마다. Fastify 기본 Ajv(draft-07)와의 호환은 P1에서 서버에 등록할 때 확인한다 **[확인 필요]**.
5. Windows에서는 "대소문자만 다른 이름"과 "루트 밖 심볼릭 링크" 음원을 만들 수 없다(파일시스템·권한). 생성기는 건너뛰고 `manifest.skipped`에 기록하며, Linux CI에서는 생성된다.
6. Windows 경로 길이: 경로가 긴 폴더에서는 `build_runner`(OS 오류 122)와 `git add`(Filename too long)가 실패했다. 저장소를 짧은 경로(`C:\AI\Clode`)에 두고 `core.longpaths=true`를 켰다.
