## 형식별 재생 표 (실기기 SM-S948N, Android 16, ExoPlayer; 2026-10-03)

앱이 보내는 `accept`: MP3, AAC(M4A), FLAC, Ogg Vorbis, Opus. 9종 모두 미디어 세션 `PLAYING` 확인.

| 원본 | 서버 결정 | 재생 |
| --- | --- | --- |
| MP3 CBR / VBR | 원본 | 됨 |
| FLAC 16비트 / 24비트 | 원본 | 됨 (01장 §2.7 "API 27+ 플랫폼 디코더" 확인) |
| AAC (M4A) | 원본 | 됨 |
| ALAC (M4A) | aac_256 변환 | 됨 (변환본) |
| Ogg Vorbis | 원본 | 됨 |
| Opus (Ogg) | 원본 | 됨 |
| WAV (PCM 16비트) | aac_256 변환 | 됨 (변환본) |

[확인 필요 남음] ALAC·WAV를 플랫폼 디코더가 직접 재생할 수 있는지는 시험하지 않았다(accept에 넣지 않아 서버가 변환). 대역폭을 아끼려면 WAV는 계속 변환하는 편이 낫다. API 26~ 다른 기기에서의 FLAC 24비트도 남음.

## 발견해 고친 것

1. **생성된 Dart 모델이 모르는 enum 값에서 역직렬화 실패** — 계약 공통 규칙("앱은 모르는 enum 값을 무시") 위반. P0의 [확인 필요]가 실제 결함이었다. 생성기 옵션 `enumUnknownDefaultCase=true`로 해결(`tools/codegen/gen-dart.mjs`).
2. **생성된 플레이리스트 편집 모델(oneOf)이 모든 필드를 필수로 만듦** — `add` 연산에 `after_item_id: null`(=맨 앞에 넣기)이 함께 나가 의미가 바뀐다. 편집은 JSON을 직접 보낸다(`ApiClient.editPlaylist`). P0에서 찾은 표지 업로드 결함과 같은 종류.
3. **대기 중이던 401이 차례로 처리되며 갱신이 여러 번 일어남** — 단일 비행 테스트가 잡았다. 요청을 보낸 토큰이 이미 바뀌었으면 다시 갱신하지 않고 새 토큰으로 재시도.

4. **(실기기) 곡이 넘어가는 순간 누른 일시정지가 무시됨** — 다음 곡을 불러오는 중에 일시정지가 들어오면, 불러오기 끝의 자동 재생이 덮어썼다. 불러오기 번호로 기억해 해결, 실기기에서 재현 후 해결 확인.
5. **(실기기, 서버) 같은 표지 동시 요청 시 500** — 썸네일 임시 파일 이름이 겹쳐 rename 실패. 고유 임시 이름 + 생성 합치기, 회귀 테스트(수정 전 실패 확인) 추가, 시험 서버 반영(`6cf71a7`).
6. **(실기기) 가로 카드 줄 고정 높이로 두 줄 제목이 넘침** — 글자 배율로 계산.

7. **(실기기, 사용자 확인) 통화 중에도 음악이 소리 없이 계속 재생** — 이 기기는 통화를 덕킹 신호로 보내는데 재생 패키지 기본 처리가 덕킹을 무시했다. 포커스 사건을 직접 처리하고 통화 모드면 일시정지, 통화가 끝난 뒤 재개(03장 §6.5 갱신, 단위 테스트 9개). 수정 후 사용자가 실기기에서 확인.

8. **(위젯 테스트) 탐색 막대의 스크린리더 증감 동작에 바뀐 값 설명이 없어 접근성 트리가 깨짐** — 몰입 화면이 매 프레임 오류. `increasedValue`/`decreasedValue` 추가.
9. **(위젯 테스트) 곡 ⋮ 메뉴 시트가 작은 화면·큰 글씨에서 넘쳐 아래 항목에 닿을 수 없음** — 스크롤 가능하게.

구조: 화면은 재생 엔진 대신 `PlayerPort` 인터페이스만 쓴다(01장 §2.5 경계를 화면 쪽에도 적용). 테스트에서 가짜로 바꿀 수 있다.

### 발음 자동 생성 (2026-10-03 추가)

기존 앱의 `pronunciation.cjs`를 서버로 옮겼다(`server/src/lyrics/pronunciation.ts`). 기존 테스트 3개(가나 변환, 사전 읽기·조사, 줄 시각 보존)를 그대로 이식해 통과(L0). 동작:

- `pronunciation_ko`가 없고 원문에 일본어가 있으면 `GET /tracks/{id}/lyrics`가 원문과 같은 시각·줄 수로 발음을 만들어 `source.type: generated`로 준다. `has_lyrics`에도 들어간다. 사이드카·직접 입력이 있으면 그쪽이 우선. 저장하지 않고 원문 해시별로 메모리에 캐시한다.
- 계약: `LyricsVariant.source.type`에 `generated` 추가(추가 변경, 앱은 `enumUnknownDefaultCase`라 옛 앱도 안전). 가사 ETag에 `-g<규칙 버전>`을 붙여 규칙이 바뀌면 앱 캐시가 무효가 된다.
- **메모리 측정**: 사전을 올리면 RSS가 약 47MB → 378MB(+330MB, 처음 불러오는 데 약 0.24초, 60줄 변환 5ms). 1GB 시험 서버에 상주시키지 않도록 **워커 스레드**에 올리고 2분 쓰지 않으면 내린다(내린 뒤 174MB). 적재 중 동시 요청도 처리(단위 테스트).
- **실기기(L3, 2026-10-03)**: 새 패키지 ID 앱(SM-S948N)에서 시험 서버(커밋 `89eb4c4`)의 `光の中へ` 가사 화면에 자동 생성 발음이 원문 아래 표시됨 — 사용자 확인.
- API 테스트: 사이드카 발음이 없는 `光の中へ` → `히카리노 나카에`, 한국어만 있는 줄은 빈 발음, 304 재검증, 사이드카가 있는 곡은 그대로 `sidecar`.
- 라이선스: kuromoji Apache-2.0, 의존성 MIT. 사전(mecab-ipadic, NAIST)은 저작권 고지·면책 문단을 함께 배포해야 한다 → 패키지의 `NOTICE.md`가 릴리스에 들어가며 앱 고지 화면에도 넣어야 한다. 목록: [`evidence/P3-server-licenses.txt`](evidence/P3-server-licenses.txt) (54개, 허용 목록 밖 0).

- `repeat=one` 상태에서 마지막 곡에서 사용자가 "다음"을 누르면 처음으로 돌아간다(03장 §6.3은 이 경우를 정하지 않음). 기존 테스트를 받으면 그쪽을 따른다.
- 여러 서버 프로필 전환 화면은 P4(FN-21)와 함께. 지금은 활성 프로필 하나이며, 다른 `server_id`로 로그인하면 이전 프로필을 정리해 토큰이 섞이지 않게 했다.
- Android가 재생할 수 있다고 보내는 형식: MP3, AAC(M4A), FLAC, Ogg Vorbis, Opus. ALAC·WAV 등은 서버가 변환한다. **[확인 필요]** 실기기 형식 표로 확정.
