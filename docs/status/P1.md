# P1 진행 보고 (서버 핵심: 인증·카탈로그·원본 스트리밍)

형식: 05장 §10.4. 작성 2026-10-02. **로컬(L1)에서 P1 수용 기준을 통과했다. SEC-05는 일부만 확인했다(아래).** L2(실서버)·L3(실기기) 검증은 하지 않았다.

환경: Windows 11, Node 24.19.0, FFmpeg/ffprobe 9.0.2, 서버 0.1.0, 합성 음원(`tools/make-fixtures --quick`).

### 테스트가 실제로 실패할 수 있는지 확인

모두 첫 실행에 통과한 묶음이 있어 두 가지를 일부러 망가뜨려 봤다: 로그의 `mt` 가리기를 끄면 SEC-10이, 경로 해석기의 루트 밖 검사를 끄면 SEC-03이 실패했다(되돌린 뒤 통과).

### 테스트로 찾아 고친 결함

- 오디오 지문을 새 파일에만 계산해서 "태그만 고친 뒤 이동" 매칭(01장 §4.3 3단계)이 동작하지 않았다 → 모든 분석 파일에 지문 저장.
- 416 오류 응답에 미디어용 `Cache-Control: immutable`·`ETag`가 붙었다(curl 세션에서 발견) → 오류 응답에서 제외, 테스트 추가.

## 증거

- [`evidence/P1-curl.txt`](evidence/P1-curl.txt): 실제 HTTP 서버(127.0.0.1)에 대한 curl 세션. 서버 정보 → 로그인 → 반각 가타카나 검색(`ﾖｱｹ` → `よあけ`) → 렌디션 → HEAD → Range 206 → 416 → 변조 티켓 401 → 로그아웃 후 티켓 무효. 토큰·티켓 값은 기록에서 가렸다.

## 구현한 것

- **저장소**: SQLite(`node:sqlite`, WAL), 전진 전용 마이그레이션(체크섬 검사, 더 새 DB 거부, 적용 전 스냅샷, 실패 시 롤백 — 단위 테스트).
- **CLI** (`server/src/main.ts`): `serve`, `admin create`(비밀번호는 대화형/표준 입력, 명령행 인자 금지), `library add|list`, `scan [--force]`, `healthcheck`.
- **인증**: Argon2id, 불투명 토큰(해시만 저장), 리프레시 회전·60초 재시도 유예·재사용 감지, 로그인 속도 제한, 같은 설치 재로그인 시 세션 대체, 비밀번호 변경 시 다른 세션 폐기, 미디어 티켓(HMAC, 자원·세션·사용자에 묶임).
- **스캐너**: 영속 ID 매핑(경로 → 내용 해시 → 오디오 지문), 이동 감지, 누락 표시, 루트 확인·빈 루트 중단, 대량 누락 보류(`--force`로 적용), 루트 밖 링크 제외, 손상 파일만 실패, 내장·폴더 표지.
- **카탈로그**: 곡·앨범·아티스트 목록(keyset 커서, 정렬 섞이면 400)·상세, 검색(NFKC·가나 통일, 3자 이상 trigram, 1~2자 접두), 변경 피드, 표지(96/256/512/1024, ETag/304).
- **미디어**: 원본 렌디션 결정(멱등), Range/HEAD/If-Range/416, 원본 변경 시 410 + 재스캔 예약, 저장소 장애 503과 파일 없음 404 구분.
- **관리 API**: 사용자 목록·생성·수정·삭제(`last_admin` 보호), 라이브러리 상태, 스캔 시작, 작업 조회.
- **요청 검증**: 라우트의 경로·쿼리·본문 스키마를 `openapi.yaml`에서 생성(`schemas.json`의 `operations`)해 Fastify에 그대로 등록. 계약과 구현의 스키마가 한 곳에서 나온다.
- **CI**: `server` 작업 추가(Ubuntu에서 FFmpeg 설치 → 합성 음원 → 타입 검사 → 테스트).

## 아직 없는 것 (P2 범위, 호출하면 404)

플레이리스트 9개 동작, 가사 3개, 재생 기록 4개, 홈, `DELETE /me`, `GET /me/export`. 변환(aac_256/128) — 지금은 원본을 재생할 수 없는 기기에 `422 no_playable_format`. `has_lyrics`는 항상 빈 배열, 검색의 `playlists`는 빈 페이지.

## 설계에서 벗어난 점 · 결정한 점 (문서 갱신함)

- 01장 §2.4: 네이티브 애드온 없이 `node:sqlite`·`node:crypto` Argon2id, TypeScript 무빌드 실행. **[확인 필요]** 릴리스 전 Node LTS에서 두 기능의 안정화 상태.
- 01장 §4.8(신설): 스키마에 추가한 컬럼과 이유(세션 회전 암호문, 라이브러리별 앨범, 정렬 키, 표지 마스터 등).
- 02장 §1.2: 모르는 리프레시 토큰은 `refresh_expired`. 02장 §6: P1에서 정한 세부 오류 동작.

## 알려진 제한

1. **CI 미실행**: 원격 저장소가 없어 Linux에서 돌린 적이 없다. Linux에서만 생기는 경우(파일 심볼릭 링크, 대소문자만 다른 이름)는 CI에서 처음 확인된다. SEC-02/03의 파일 링크 형태도 마찬가지.
2. 0바이트처럼 분석에 실패한 파일은 매핑이 없어 스캔할 때마다 다시 분석한다(실패 1건으로 기록). 큰 라이브러리에서 실패 파일이 많으면 비용이 된다 → P2에서 실패 기록 캐시 검토.
3. 태그 변경으로 곡이 다른 앨범으로 옮겨 가면 빈 앨범·아티스트는 숨겨지지만 변경 피드에 삭제 통지(tombstone)는 아직 나가지 않는다 → P2 "누락 곡 정리"와 함께.
4. 로그인 속도 제한은 메모리에 있어 재시작하면 초기화된다(단일 프로세스 가정).
5. 스캔·지문 처리량, 메모리 사용은 아직 측정하지 않았다(P2 측정 항목).
